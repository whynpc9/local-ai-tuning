# DFlash 2 调研：公开复现边界与本地推理采用门

> 截止时间：2026-08-19。本文核对公开文章、模型卡、配置、代码与上游 PR；未在本工作区的目标硬件上重跑性能，因此所有吞吐数字仍是外部证据，不能直接晋级为本仓库推荐值。

## 结论

DFlash 2 是值得立即进入 Qwen3.8-27B 实验矩阵的低延迟 speculative-decoding challenger，但还不应替代 native MTP 默认值。

- 它不是让 diffusion model 直接输出最终答案，而是用 block-diffusion drafter 一次并行提出一个 token block，再由 target model 验证。
- Qwen3.8-27B 的公开 checkpoint、配置、BF16/GGUF 权重和推理代码已经存在；旧的“closed/private、不可公开复现”判断从 2026-08-18 起失效。
- 官方 H200/SGLang 数据显示 C1 明显领先 MTP 和社区 DSpark，但高并发收益快速缩小，且没有可审计 raw results、重复/方差、长上下文曲线、显存、功耗或 TTFT/TPOT 分解。
- SGLang 支持已进入 upstream main；vLLM 与 llama.cpp 仍依赖未合并 PR；Apple 路线是 z-lab 的 oMLX fork/prebuilt，不是 jundot/oMLX 正式 release。
- 当前公开 drafter只覆盖 Qwen3.8-27B 与 Muse Glimmer。不要把 Qwen 结果外推到 DeepSeek-V4-Flash-0731。

## 它相对 DFlash 增加了什么

初代 DFlash 让 block 内每个位置在一次 drafter forward 中并行预测，避免 autoregressive drafter 的逐 token 串行成本。DFlash 2 保留这个一遍并行 backbone，针对两个接受率损失来源增加小模块。

### Candidate path selector

DFlash 2 在每个位置保留 top-16 token，并对相邻位置的候选对打分。打分由 drafter 原始 unary logit 加一个 rank-256 的低秩双线性交互组成。所有 pair score 并行计算；最后只在预计算分数上走一条短路径。

官方 Qwen3-4B ablation 中，selector 增加约 2.0M 参数和 0.6% draft-verify cycle latency，接受长度从 4.27 提升到 4.61；同一设置下 DSpark correction 增加 77.8M 参数和 9.6% cycle latency，接受长度为 4.49。这个对比支持“从候选中选择比重新 autoregressive 修正更便宜”，但仍是作者实验，不是本地独立复现。

### Two-tap dynamic convolution

初代 DFlash 的 candidate recall 随 block 后缀下降。DFlash 2 在每个 drafter layer 的 attention 和 MLP 子层前后加入两 tap dynamic depthwise convolution：当前位置混合自身与前一位置，第一位置读取上一个已验证 token。模块是 block-local、stateless，仍保持各位置并行。

官方 ablation 中，convolution 增加约 16.5M 参数（相对五层 drafter 约 3%）和 0.7% cycle latency；selector 与 convolution 合计增加约 1.3% cycle latency。完整方法在作者的跨任务实验中比初代 DFlash 多接受约 16-25% 输出。

原理、公式和 ablation 见 [DFlash 2 官方文章](https://inco.ai/blog/dflash2/)。初代方法的同行评审来源是 [DFlash ICML 2026 论文](https://arxiv.org/abs/2602.06036)；DFlash 2 截止本文只有工程文章，没有独立论文。

## Qwen3.8-27B 公开 artifact

官方公开 checkpoint 是 [`incoai/Qwen3.8-27B-DFlash2`](https://huggingface.co/incoai/Qwen3.8-27B-DFlash2)，本文核对 revision：

```text
dedf8df68adfb1afeaf7b7480c0a0243108177b4
```

模型无 gate、Apache-2.0，只是 draft model，不能独立生成。配置的关键字段：

| 字段 | 值 |
|---|---:|
| architecture | `DFlash2DraftModel` |
| dtype | BF16 |
| hidden layers | 5 |
| hidden size | 5120 |
| attention heads / KV heads | 32 / 8 |
| block size | 8 |
| candidate top-k | 16 |
| selector rank | 256 |
| dynamic convolution | kernel 2, group 16 |
| target hidden layers | 5, 19, 33, 47, 61 |
| sliding window | 2048 |
| max position | 262144 |

权重文件约 3.85 GB，按 BF16 文件体积约为 1.92B 参数。公开 [GGUF 仓库](https://huggingface.co/incoai/Qwen3.8-27B-DFlash2-GGUF) 同时提供：

| Artifact | 文件大小 |
|---|---:|
| BF16 GGUF | 3,860,293,152 bytes |
| Q8_0 | 2,056,414,752 bytes |
| Q4_K_M | 1,143,006,752 bytes |

这些只是静态权重大小，不是运行峰值。还要计入 target、draft KV、target hidden-state injection、verification buffers、graph capture、runtime allocator 和系统保留；不能用 1.14/3.85 GB 直接推导可用 context。

固定配置见 [config.json](https://huggingface.co/incoai/Qwen3.8-27B-DFlash2/blob/dedf8df68adfb1afeaf7b7480c0a0243108177b4/config.json)，模型说明与作者吞吐表见 [model card](https://huggingface.co/incoai/Qwen3.8-27B-DFlash2/blob/dedf8df68adfb1afeaf7b7480c0a0243108177b4/README.md)。

## 官方性能证据能说明什么

作者使用一张 NVIDIA H200、SGLang、target/draft FlashAttention 3、block size 8、Qwen 官方 sampling、`xhigh` reasoning、最大 4096 new tokens，对 GSM8K、MATH-500、HumanEval、MBPP、MT-Bench 进行比较。

平均 acceptance length：

| MTP | DSpark | DFlash 2 |
|---:|---:|---:|
| 4.28 | 3.62 | 4.80 |

DFlash 2 相对 MTP 高约 12%，相对社区 DSpark 高约 33%。作者报告的 output-token E2E throughput：

- C1：184.0-236.1 tok/s，为 autoregressive 的 2.67-3.43 倍，比 MTP 高约 32-48%。
- C8：1,090.2-1,368.3 aggregate tok/s，为 autoregressive 的 2.27-2.85 倍。
- C32：1,525.3-1,951.8 aggregate tok/s，只剩 autoregressive 的 1.01-1.45 倍。

因此最强信号是低并发 decode，不是饱和 batch 下的通用吞吐倍增。高并发时 MTP/DSpark 在多个任务上已经慢于 autoregressive，DFlash 2 虽仍最好，边际收益也明显缩小。

### 证据缺口

公开模型卡没有绑定 target revision、SGLang commit、container digest、prompt token shape 或 dataset snapshot，也没有提供：

- raw request/result 文件；
- 重复次数、CV、置信区间和运行顺序；
- TTFT、TTFO、TPOT/ITL 分布；
- reasoning tokens 与 visible-answer tokens 分账；
- drafter prefill 开销、显存峰值、功耗和热状态；
- 长上下文 acceptance falloff、prefix-cache 条件和 context ceiling；
- tool、strict JSON、vision、多轮 agent trajectory 的质量门。

“lossless”成立的前提是 target verification 和 rejection sampling 实现正确：greedy 应与同一 target/config 逐 token 相等；sampling 应保持同一 target distribution。量化 target 的“相同输出”只相对该量化 target，不代表等同 BF16 target。runtime bug、parser/template 差异或错误的 verifier 仍可能破坏产品行为，必须本地验证。

## Runtime 状态

状态随 upstream 快速变化，以下结论只对应 2026-08-19。

| Runtime | 状态 | 采用边界 |
|---|---|---|
| SGLang | [`#35371`](https://github.com/sgl-project/sglang/pull/35371) 已合并，merge commit `c14312a66420b75ca9a11bf1817c4db1fa26b097` | 当前首选 CUDA 入口；量化 target LM head 的 [`#35462`](https://github.com/sgl-project/sglang/pull/35462)/[`#35496`](https://github.com/sgl-project/sglang/pull/35496) 仍开放 |
| vLLM | 核心 [`#52816`](https://github.com/vllm-project/vllm/pull/52816) 和量化配置 guard [`#52883`](https://github.com/vllm-project/vllm/pull/52883) 均未合并 | 只能 pin PR/fork；不能写成 released support |
| llama.cpp | [`#27342`](https://github.com/ggml-org/llama.cpp/pull/27342) 未合并 | CUDA/Metal/ROCm 可实验；multimodal M-RoPE、平台 CI、并发和不同 GPU 的最佳 draft cap 仍需验证 |
| oMLX | z-lab fork 发布 [`0.6.2-dflash2`](https://github.com/z-lab/omlx-fork/releases/tag/0.6.2-dflash2) signed DMG | 不是 jundot/oMLX 上游 release；已有 [continuous batching 缺失报告](https://github.com/jundot/omlx/issues/2854) |
| `z-lab/dflash` | MIT、版本 `0.1.0` beta，本文核对 commit `07ebd93db9f472af339b644bb70221ad8428328a` | 包含推理/benchmark；当前 tree 未见 DFlash 2 training entrypoint/recipe |

初代 DFlash 已有更广的 runtime/model 覆盖，不代表 DFlash 2 自动继承所有组合。尤其不要把初代 TensorRT-LLM、旧 oMLX `dflash-mlx` registry 或其他模型 checkpoint 的支持写成 DFlash 2 支持。

## 对目标硬件的采用判断

### DGX Spark / GB10 / SM121

Qwen3.8 target 和 BF16/量化 drafter在 128 GB UMA 上具备容量候选资格，但官方 H200/FA3 结果不能外推到 273 GB/s UMA。使用 SGLang main 的精确 merge 后 revision，先跑 official/FP8 target-only，再加 DFlash 2；如果使用社区 NVFP4 target，必须先通过量化 LM-head loader/kernel gate。记录 UMA resident peak、swap/pageout、draft hidden/KV、prefix cache 与 context ceiling。

### RTX PRO 6000 / SM120

96 GB GDDR7 对 Qwen target + BF16 drafter有容量空间，单流 memory-bandwidth 条件也更接近适合 speculative decoding 的场景。仍需证明 SM120 的 attention/top-k/convolution kernel 路径，没有 H200-only backend或 fallback。先使用 SGLang main；vLLM 与 llama.cpp 保持独立 PR-pinned challenger，不混入 release lane。

### Apple Silicon

DFlash 2 已从“不可复现”变为“公开但早期”。可以使用 `z-lab/dflash` MLX backend或 `z-lab/omlx-fork` 预编译包建立 challenger，但不能把 fork 的结果归因于 jundot/oMLX v0.6.2。对 4-bit target/draft，公开实现建议 `block_size <= 5`，因为当前 MLX quantized matmul 在更宽 verify block 下效率下降。

Apple 必测额外统一内存、draft prefill、swap/compression/pagein、长上下文、continuous batching、tool/JSON/vision。native MTP 与 DFlash 是互斥 lane，要共享 target artifact、prompt、sampling、质量门和热状态进行比较。

### DeepSeek-V4-Flash-0731

没有匹配的公开 DFlash 2 drafter。保留 target-only、native/Lightning MTP、DSpark 与已验证的 DFlash/其他 speculative lane，不从 Qwen3.8 或 Muse Glimmer 的 acceptance/throughput 推导 DeepSeek 收益。

## 本仓库的实验合同

对 Qwen3.8-27B，至少建立四个同 target control：

1. autoregressive；
2. native MTP，按 runtime 的真实深度语义扫描；
3. external DSpark，固定 draft revision和 cap；
4. DFlash 2，固定 `dedf8df...`、runtime commit、block size、draft quantization。

每个 candidate 必须单独记录 target/draft revision、artifact hash、runtime/image digest、chat template、reasoning effort、sampling、KV/cache、context、power/thermal 与 client location。不要把官方 BF16 target、社区 NVFP4 target、GGUF target 和 Apple MLX quantization 放在同一 common-denominator comparison contract。

建议矩阵：

- workload：reasoning、code、prose、tool、strict JSON；
- shape：2K/8K/32K input × 512 output，另加产品真实 trace；
- concurrency：C1/C8/C32；
- cache：cold engine、warm engine/cold prefix、warm shared prefix分开；
- DFlash 2：CUDA 先测 block/draft 3/5/7；量化 MLX 上限先到 5；
- 指标：TTFT、TTFO、TPOT/ITL、E2E、completion tok/s、visible-answer tok/s、goodput、acceptance length/per-position、draft/verify cycle、错误/超时/截断；
- 资源：target/draft/cache/graph peak memory、context ceiling、功耗、温度、Apple swap/compression/pagein。

晋级门：

- temperature 0 与相同 target/config 逐 token 相等；
- sampling、tool、JSON、reasoning、长上下文和 vision 按产品合同无回归；
- 至少七次交错 trial，最低增益与 observed-range/CV 门通过；
- 产品 workload 的 E2E 或 SLO goodput 明确领先 MTP，而不是只看最佳 code burst decode；
- 额外内存、prefill、context ceiling 和并发退化在事先声明的预算内；
- runtime 路径没有静默回退、unsupported kernel、错误 architecture dispatch 或未合并依赖漂移。

在这些门完成前，DFlash 2 的仓库定位是：**公开、可运行、强先验、C 级性能证据的 challenger**。
